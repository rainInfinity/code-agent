## Context

当前主窗口由 Tauri 配置静态创建，Trace 窗口由 `open_trace_window` 在运行时创建。Trace 已具备独立窗口位置/尺寸持久化、hide/show、无边框自定义标题栏、pin 和 always-on-top 控制。新增贴靠能力需要跨 Rust 窗口管理、前端 IPC、Trace 标题栏控件和持久化状态协作。

贴靠模式不是把 Trace 嵌入主窗口 DOM，而是让两个 OS 窗口形成受约束的并排关系。这样可以保留 Trace 独立窗口的调试工具属性，同时在主窗口移动、最大化、最小化和恢复时提供稳定的伴随体验。

## Goals / Non-Goals

**Goals:**
- 支持 Trace 在独立窗口、贴靠左侧、贴靠右侧之间切换。
- 贴靠时根据主窗口几何实时计算 Trace 位置和高度。
- 主窗口最大化时将 Trace 放到主窗口内侧，并在贴靠期间强制置顶。
- 主窗口最小化/恢复时同步隐藏或恢复 Trace，并重新应用贴靠几何。
- 单独保存贴靠侧、贴靠宽度和进入贴靠前的置顶状态，不覆盖独立窗口几何。
- 贴靠模式下禁用最大化，拖拽标题栏时退出贴靠。

**Non-Goals:**
- 不把 Trace 改造成主窗口内部面板或 split view。
- 不重做 Trace 内容面板、滚动跟随、turn 展开逻辑或数据同步协议。
- 不改变 pin 的对话切换语义。
- 不引入第三方窗口布局依赖。

## Decisions

1. 贴靠作为窗口级状态由 Rust 侧作为权威来源管理。
   - 选择：新增 Trace docking state，包含 `mode`、`side`、`attachedWidth`、`previousAlwaysOnTop` 等字段，由 Tauri 命令和窗口事件更新。
   - 理由：贴靠位置依赖 OS 窗口坐标、最大化/最小化状态和显示器可用区域，Rust 侧能直接读取和设置主窗口与 Trace 窗口几何。
   - 备选：前端监听窗口事件并通过 JS API 计算几何。淘汰原因是前端需要更多异步 IPC 往返，且主窗口最大化和多显示器边界处理更脆弱。

2. 独立窗口几何和贴靠几何分开持久化。
   - 选择：保留现有 `trace` 独立窗口位置/尺寸保存逻辑，新增贴靠专用状态，例如 `traceDocking: { mode, side, attachedWidth }`。
   - 理由：用户退出贴靠后应回到之前熟悉的独立窗口尺寸和位置；贴靠拖宽不应污染独立窗口宽度。
   - 备选：复用现有 window-state 的 trace width。淘汰原因是会让贴靠宽度和独立窗口宽度互相覆盖。

3. 主窗口最大化时贴靠到主窗口内侧。
   - 选择：主窗口未最大化时，Trace 贴在主窗口外侧；主窗口最大化时，Trace 使用主窗口 bounds 的内侧区域，左贴靠覆盖主窗口左侧区域，右贴靠覆盖主窗口右侧区域。
   - 理由：最大化窗口外侧通常没有可见空间；内侧贴靠配合强制置顶可以保证 Trace 可见。
   - 备选：最大化时自动退出贴靠。淘汰原因是会破坏用户明确选择的贴靠工作流。

4. 贴靠期间强制 always-on-top，退出后恢复进入贴靠前的状态。
   - 选择：进入贴靠时记录当前 always-on-top，随后强制设置 Trace 置顶；贴靠期间置顶按钮显示为强制激活且不可关闭；退出贴靠时恢复记录值。
   - 理由：主窗口最大化内侧贴靠时，如果 Trace 不置顶，会被主窗口遮挡。
   - 备选：只在进入贴靠时默认开启置顶。淘汰原因是用户关闭置顶后最大化场景会失效。

5. 贴靠宽度由 Trace 窗口 resize 结果驱动并 clamp。
   - 选择：允许用户通过 OS 窗口边缘拖拽 Trace 宽度，Rust 在 Trace `Resized` 后读取实际宽度，约束到最小/最大范围并保存为 `attachedWidth`，再重新应用贴靠位置。
   - 理由：保留系统级 resize 手感，并让约束逻辑集中在窗口管理层。
   - 备选：前端自绘拖拽分隔条。淘汰原因是 Trace 是独立 OS 窗口，自绘分隔条无法自然控制主窗口外侧窗口边缘。

6. 标题栏拖拽是退出贴靠的明确意图。
   - 选择：贴靠模式下用户在 Trace 标题栏开始拖拽时，先调用退出贴靠命令，再启动正常窗口拖拽。
   - 理由：拖动标题栏在桌面窗口语义里代表“我要把它移走”；自动吸回会让用户感到失控。
   - 备选：贴靠期间禁止标题栏拖拽。淘汰原因是缺少自然的脱离手势。

## Risks / Trade-offs

- [Risk] 多显示器、DPI 缩放和最大化 bounds 在不同平台上可能有细微差异。→ 使用 Tauri 的物理坐标和窗口 bounds API，所有贴靠计算统一在 Rust 侧完成，并通过手动验证覆盖单屏、多屏、最大化场景。
- [Risk] 主窗口快速移动或 resize 时 Trace 可能出现短暂滞后。→ 在主窗口 move/resize 事件中去抖保存状态，但贴靠几何同步应即时或轻量节流，不等待持久化 debounce。
- [Risk] 贴靠期间 Trace 强制置顶可能遮挡其他应用。→ 该约束仅在贴靠模式生效；退出贴靠立即恢复进入贴靠前的置顶状态。
- [Risk] 贴靠宽度过大可能压住主窗口主要内容，尤其在最大化内侧贴靠时。→ 设置最大宽度，并可基于主窗口宽度限制为一个比例上限。
- [Risk] 现有 Trace pin/always-on-top 合并按钮语义可能与贴靠强制置顶相冲突。→ 贴靠期间按钮展示强制激活状态并禁用置顶切换，文案说明为贴靠时保持在前。
