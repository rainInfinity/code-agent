## Context

当前设置弹窗为单列 520px 滚动布局，将所有设置项平铺在三个 Section 中。随功能扩展，这种布局难以导航。同时窗口初始化存在从默认尺寸跳变到保存尺寸的闪烁，工作模式切换和工作目录管理分散在设置弹窗和侧边栏两处。

技术栈：Tauri v2 + React + TypeScript + styled-components + Zustand。窗口为 frameless 自定义标题栏。

## Goals / Non-Goals

**Goals:**
- 窗口首次显示即为保存的尺寸，无视觉跳变
- 设置弹窗具备左侧分类导航 + 右侧内容的布局，提升可导航性
- 工作模式切换整合到主界面侧边栏，方便一键切换
- 编程模式的项目目录管理完全在侧边栏完成，设置中不再包含此功能

**Non-Goals:**
- 不改变设置的持久化机制（仍通过 Rust 后端 `save_settings` 命令）
- 不改变 provider 切换、API key 保存、模型列表加载等核心业务逻辑
- 不新增设置项，仅重新组织现有设置项的布局
- 不改变窗口状态保存/恢复的文件格式和逻辑

## Decisions

### 1. 窗口闪烁修复：`visible: false` + 恢复后 `show()`

**选择**：在 `tauri.conf.json` 中将窗口设为 `visible: false`，在 `setup()` 中调用 `restore_window_state()` 后立即调用 `window.show()`。

**备选方案**：通过 `WebviewWindowBuilder` 在创建窗口前读取保存的尺寸并传入。这需要拦截 Tauri 默认的窗口创建流程，实现复杂度高，且 Tauri v2 的 `setup` 阶段窗口已创建完毕，用 `WebviewWindowBuilder` 需关闭原窗口重建。

**选择理由**：改动最小——仅需修改 config 一个字段和 lib.rs 添加一行 `show()` 调用。窗口从不可见到可见仅一帧，首次可见时即为正确尺寸。

### 2. 设置弹窗：状态驱动的 section 切换

**选择**：在 `SettingsModal` 内部使用 `useState<'general' | 'api'>` 管理当前选中的分类，通过条件渲染切换右侧内容区。仅保留"通用"和"API 配置"两个分类，模型选择合并到 API 配置分类中。

**备选方案**：每个分类独立 tab 组件、或使用路由参数。但设置弹窗是一个独立浮层，无 URL 暴露，状态驱动最为简单直接。

**选择理由**：
- 避免引入路由依赖
- 切换 section 时保留已填写的表单草稿状态（`drafts`）
- 与现有的 `drafts` 状态管理兼容，切换 provider 的逻辑无需更改

### 3. 设置弹窗尺寸和布局调整

**选择**：弹窗宽度从 520px 增加到 660px，以适应侧边栏 + 内容区的双列布局。弹窗使用固定高度 480px，移除标题栏（"设置"标题和关闭按钮），关闭按钮移至右下角与保存/取消同排。侧边栏高度占满整个弹窗。

布局比例：左侧导航 ~160px 高度占满，右侧内容区 ~460px，间距 40px。

**选择理由**：
- 固定高度避免内容切换时弹窗高度跳变
- 移除标题栏释放垂直空间，侧边栏全高视觉更整洁
- 关闭按钮移至底部与取消/保存统一操作区

### 4. 模式切换：侧边栏顶部分段控件

**选择**：在侧边栏顶部添加一个两段分段控件（Segmented Control），直接读写 `settingsStore.agentMode`。

**备选方案**：放在标题栏。但标题栏已有菜单和窗口控件，空间紧张，且模式切换与侧边栏的会话列表和项目目录紧密关联，放在侧边栏逻辑内聚性更好。

**选择理由**：
- 模式切换直接影响侧边栏显示内容（编程模式下出现项目选择器）
- 侧边栏顶部有充足空间容纳两段控件
- 切换模式时，`effectiveWorkDir` 自动更新，过滤会话列表

### 5. 项目目录添加：Tauri dialog.open 纯浏览模式

**选择**：编程模式下在侧边栏的 WorkDirSelector 旁增加浏览按钮，点击调用 `@tauri-apps/plugin-dialog` 的 `open()` 选择目录，确认后将路径通过 `settingsStore.addWorkingDirectory()` 添加到列表。不提供手动输入路径的回退方式。

**备选方案**：同时保留手动输入。但原生对话框已覆盖所有场景，保留输入框增加侧边栏复杂度却无实际收益。

**选择理由**：
- 原生对话框用户体验优于手动输入，且不会输错路径
- 侧边栏空间有限，单一浏览按钮保持简洁
- 移除手动输入可减少侧边栏代码量和维护负担

### 6. 设置分类内容划分

| 分类 | 图标 | 内容 |
|------|------|------|
| 通用 | FaGear | 主题切换（深色/浅色）|
| API 配置 | FaKey | 提供商选择、API Key 输入、自定义端点、模型下拉选择、刷新按钮 |

工作模式从设置中移除。工作目录管理从设置中移除。API 配置和模型合并在同一分类下，减少导航层级。

### 7. 模式切换确认：流式响应进行中时弹窗确认

**选择**：当用户切换工作模式且当前有流式响应正在进行中时，弹出确认对话框提示用户切换模式将中断当前响应。

**备选方案**：直接切换不提示。但会丢失进行中的响应内容，造成用户困惑和数据丢失。

**选择理由**：
- 使用 `window.confirm()` 或 Tauri 原生对话框，实现简单
- 仅在 `chatStore.isStreaming === true` 时触发，不影响正常切换
- 用户取消时保持当前模式和响应状态不变
- 用户确认后中断流式响应并切换模式

## Risks / Trade-offs

- **窗口 hidden 启动**：若 `restore_window_state()` 因读取文件失败而未设置尺寸，窗口将以默认 1200x800 显示后再 show，但此情况极少见（仅在首次启动且无配置文件时）。→ 在 `tauri.conf.json` 中保留 width/height 作为 fallback
- **侧边栏信息密度增加**：添加模式切换和目录选择后，侧边栏内容变多，小屏幕下可能拥挤。→ 编程模式下仅当有工作目录时才显示目录选择器；section 标题紧凑
- **设置弹窗变宽**：660px 在小屏幕（如 1024px 宽）下接近屏幕宽度。→ `max-width: 90vw` 已有，保证不会超出视口
- **dialog.open 权限**：需要确认 `tauri-plugin-dialog` 已正确配置权限。→ 检查 capabilities 配置
