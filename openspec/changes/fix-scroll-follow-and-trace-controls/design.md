## Context

当前主聊天窗口已有自动滚动、近底部阈值和“滚动到最新”按钮，但状态判断主要依赖内容变更后的滚动距离，容易在内容刚撑出滚动条、流式 markdown 高度变化、窗口高度变化时把“仍应跟随”误判为“用户已离开底部”。Trace 窗口此前只有普通滚动容器，缺少自动跟随和统一的 turn 展开状态管理。

本次变更涉及两个 UI 面：主聊天消息列表和独立 Trace 窗口。两者都需要尊重用户主动滚动，又要在 AI 正在生成、用户仍在底部或近底部时稳定保持最新内容可见。

## Goals / Non-Goals

**Goals:**
- 在主聊天和 Trace 窗口中实现一致的自动贴底语义：近底部时跟随，用户主动离开时暂停。
- 覆盖内容高度增长、滚动容器尺寸变化、从无滚动条到出现滚动条的边界场景。
- 在 Trace 窗口中提供清晰的三类控制：合并后的保持打开/置顶按钮、全部打开/全部收起开关、跟随最新开关。
- 将 Trace turn 展开状态提升到 `TracePanel` 统一管理，使全局模式能控制已有 turn 和后续新增 turn。

**Non-Goals:**
- 不改变 Agent 流式事件、Trace IPC 或后端协议。
- 不引入新的持久化格式；Trace 展开模式和跟随最新模式仅作为当前窗口 UI 状态。
- 不重做 Trace 面板视觉体系或单个 Prompt/Thinking/Response 内容块的内部滚动行为。

## Decisions

1. 使用“用户滚动意图”而不是所有 scroll 事件来打断自动跟随。
   - 程序化滚动和内容高度变化也会触发 scroll，如果直接据此关闭跟随，会复现被挤上去的问题。
   - 方案是在 wheel、touch、键盘滚动和滚动条拖动等真实输入上记录短暂用户意图窗口；只有这些输入导致离底时才暂停跟随。

2. 在流式运行期间使用 `requestAnimationFrame` 持续贴底。
   - ResizeObserver 和 store subscription 都可能早于最终布局完成，单次补滚会漏过后续高度增长。
   - 跟随状态开启时，每帧将 `scrollTop` 设为 `scrollHeight`，直到生成结束或用户主动离开。

3. 同时监听内容容器和滚动容器尺寸变化。
   - 内容增长影响 `scrollHeight`，窗口高度变化影响 `clientHeight`。
   - 两者都应触发一次滚动同步，覆盖窗口 resize、Trace 面板最大化/还原、从无滚动条到有滚动条的变化。

4. Trace 展开状态由 `TracePanel` 管理。
   - `TurnCard` 内部状态无法被“全部打开/收起”和“跟随最新”统一控制。
   - `TracePanel` 以 turn key 集合保存展开状态，并在新 turn 到来时按当前模式更新。

5. Trace 控制按钮使用开关语义。
   - 保持打开和置顶合并为一个图钉按钮：未完全开启时点击同时开启，两者都开启时点击同时关闭。
   - 全部打开/收起按钮根据当前是否全部展开切换行为。
   - 跟随最新按钮可开启/关闭；开启时只展开最新 turn，并在新 turn 到来时继续保持该模式。

## Risks / Trade-offs

- [Risk] 流式期间每帧贴底可能增加少量 UI 工作量。→ 只在生成/Trace running 且自动跟随开启时执行，且操作仅为轻量 scrollTop 赋值。
- [Risk] 用户点击 Trace 内部按钮可能被误认为滚动意图。→ 只把滚轮、触摸、键盘滚动，以及发生在滚动容器本体上的 pointer down 视作滚动意图。
- [Risk] 跟随最新模式与手动展开历史 turn 存在冲突。→ 用户手动切换某个 turn 展开状态时退出跟随最新模式，避免模式和手动查看互相抢控制权。
- [Risk] 合并保持打开和置顶后减少了单独控制自由度。→ 该变更符合当前需求，把 Trace 窗口作为排查辅助窗口时的常用组合行为收敛为一个入口。
